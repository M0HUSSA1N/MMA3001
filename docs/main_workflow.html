Combined Cycle Power Plant electrical output prediction: sequential analysis workflow.

This page describes the executable script rather than an importable function API. The five reusable functions are documented in main_model_functions.html.

1. Execution & environment

Run the analysis from the repository root after installing the pinned dependencies and placing the Excel workbook under data/. File paths are resolved relative to the directory containing main.py, not to a machine-specific absolute path.

# Inside the project directory, with Python 3.13 available
python -m pip install -r requirements.txt
python main.py

# Verify the generated results
python -m pytest test_main.py -v

The script starts automatically when executed, prints progress and model metrics to the terminal, writes CSV tables under results/, and saves visualisations under figures/. Running it again regenerates or overwrites the named outputs.

Do not generate pdoc by importing main. Because main.py has top-level executable statements, importing it can trigger dataset loading and model training. Generate the API documentation with python -m pdoc main_model_functions test_main -o docs. This documents the helper and test functions without importing the executable main script.

4. Ten-stage workflow

Stage 01: Dataset loading and cleaning

Locate data/Folds5x2_pp.xlsx, enforce the five required fields, reject missing/non-finite or non-numeric values, remove exact duplicates and print the resulting row counts. No imputation is needed for the provided workbook.

Stage 02: Exploratory data analysis

Compute Pearson correlations between AT, V, AP, RH and PE; save an annotated heatmap to figures/correlation_heatmap.png. Correlations support descriptive interpretation; they do not establish causality.

Stage 03: Reproducible dataset partition

Use random_state=42 to split the 9,527 cleaned observations into 6,668 training (70%), 1,429 validation (15%) and 1,430 independent test (15%) observations. The test subset is not used for fitting scalers or selecting hyperparameters.

Stage 04: Multiple Linear Regression baseline

Fit LinearRegression to the initial training observations; evaluate on validation data and inspect coefficients. MLR is the interpretable low-complexity reference against which nonlinear methods are assessed.

Stage 05: Support Vector Regression tuning

Evaluate 60 RBF-SVR configurations using C, epsilon and gamma. Standardisation occurs inside each pipeline fitted to training data. Record validation MAE, RMSE, R², fit/prediction timings and support-vector counts; choose the lowest validation RMSE.

Stage 06: Artificial Neural Network tuning

Evaluate 36 MLPRegressor configurations varying hidden-layer architecture, L2 regularisation and initial learning rate. Record training and validation metrics, training iterations, trainable parameters and convergence warnings. Select using external validation RMSE; early stopping additionally uses an internal split of fitting data.

Stage 07: Final refitting and held-out evaluation

Refit each selected model on 8,097 combined training and validation records and evaluate it on the same untouched 1,430-record test partition. Store final MAE, RMSE, R² and timing. Report coefficients from the final MLR fit, which differ slightly from the initial training-only coefficients.

Stage 08: Final test visualisations

Produce the RMSE comparison, actual-versus-predicted plots and predicted-versus-residual plots for all three regressors. Residuals are defined as actual minus predicted; unusually large residuals are retained unless independent evidence establishes a record is invalid.

Stage 09: Accuracy-computational-cost analysis

Measure and compare final-fit time, median inference time over 20 repeated predictions on the full test batch, architecture/parameter counts and approximate arithmetic operations per prediction. Plot test RMSE against measured prediction time.

Stage 10: Regional performance and engineering plausibility

Compute test errors for low, moderate and high ambient-temperature regions using training-derived temperature thresholds. Check predictions against the historical target range; then vary temperature across its training 5th-95th percentile while fixing other inputs at training medians to inspect response direction.

6. Verification & reproducibility

The test suite is implemented in test_main.py, with 13 pytest tests covering helper functions, invalid inputs, model construction and saved workflow outputs. Run main.py before pytest on a new clone because certain tests expect generated CSV files.

python main.py
python -m pytest test_main.py -v

# Windows PowerShell: display output and overwrite the test report
python -m pytest test_main.py -v 2>&1 | Tee-Object -FilePath test_report.txt

Test coverage includes required columns and invalid input handling, duplicates, split integrity, metric calculations, model-building behaviour and a workflow-output check. The additional workflow test checks main.py syntax plus five generated CSV files and seven PNG files; it does not execute model training during pytest. A passing test suite verifies the checked program behaviour; it does not prove predictive accuracy on future plants or all engineering use cases.

Reproduction checklist

  1. Use Python 3.13.0 and install requirements.txt.
  2. Confirm data/Folds5x2_pp.xlsx contains AT, V, AP, RH, PE.
  3. Run python main.py and inspect the terminal summaries.
  4. Confirm five CSV outputs in results/ and seven PNGs in figures/.
  5. Compare final accuracy metrics with the table above; measured runtimes are machine-dependent.
  6. Run pytest; confirm that all 13 tests pass, and save test_report.txt if needed.

7. Computational analysis & timing

The final script records single-fit training times and uses the median of 20 repeated test-batch predictions for inference timing. Timing repetitions occur after fitting and a warm-up prediction, and do not change model parameters or prediction metrics. Results below are from a Windows/Python 3.13.0 execution; they are not guaranteed on other hardware.

MetricMLRANNSVR
Final fit time (s; one fit)0.004414.97639.5861

Approximate basic arithmetic operations / observation82,95072,898

SVR retains 5,207 support vectors in the final refit. Its estimate is 5,207 × (3 × 4 + 2) = 72,898 basic operations per observation, excluding approximately 5,207 RBF exponentials, scaling and implementation costs. ANN's 4-50-25-1 architecture has 1,475 weights plus 76 biases; its estimate 2 × (4×50 + 50×25 + 25×1) = 2,950 excludes biases, nonlinear activations and scaling. These are simplified operation estimates, not fully measured hardware FLOPs.

SVR inference was about 1,044 times slower than ANN in the latest measured run, using unrounded prediction times. This ratio varied substantially between runs. Prediction time is sensitive to platform, workload and library implementation; repeating calls reduces noise but does not establish general hardware-independent latency. Training durations are single measurements.

9. Assumptions, error handling & limitations

  • Operating scope: historical, hourly averaged full-load observations from one CCPP. Other plants, future periods, part-load regimes and transients are not validated.
  • Validation scope: a single reproducible random partition and fixed ANN seed. Alternative partitions, cross-validation and additional ANN initialisations would provide stronger stability evidence.
  • Parameter scope: the reported configurations are the best within the investigated grids; the winning SVR C, epsilon and numeric gamma, and ANN alpha, lie at explored upper boundaries.
  • Data validation: missing files/columns, non-numeric, missing and infinite observations are rejected. Physical out-of-domain constraints and unusual but numeric combinations are not fully enforced.
  • Inference timing: short operations can be dominated by memory, runtime and library overhead. Measured results are not a controlled cross-platform benchmark.
  • Intended use: offline performance estimation and evaluation only; not a production forecaster, equipment controller or safety-critical application.
  • Data chronology: the supplied workbook does not provide the original time stamps required for true chronological testing.

Reproducibility limits: the fixed split and pinned dependencies support repeatable comparisons, but exact wall-clock timings vary. No model checkpoint is exported; rerun main.py to reconstruct fitted models and outputs.
